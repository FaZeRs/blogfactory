# Localization (sub-project 5): design spec

Date: 2026-11-07. This is sub-project 5 of `2026-11-03-blog-engine-design.md`. The owner merged sub-projects 3 and 8 and the subscription models, and asked for the next phase. The Lindevo blog publishes English and Latvian, and its engine localizes every post (`apps/content-engine/src/stages/localize`, surveyed 2026-11-07). This ports that flow, generalized so that any site can add second languages.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Who and which languages | **Per site:** `user_settings.localization = { enabled, locales: [{ locale: "lv", name: "Latvian", glossary: [{source, target, note?}], styleGuide: string, formalAddress?: { forbidden: string[] } }] }`. The default is off. | Lindevo needs Latvian; other sites may want other languages. Glossary and style live in data, not code. |
| When | A new engine stage, **`localize`**, after the run passes gates and review and before `deliver`, for every enabled locale. It also runs **on demand** for any existing post ("Translate" / "Update translation"). | It matches Lindevo's order (localize after the English is final), and it lets edited posts be re-localized. |
| Failure | The stage can be skipped: a failed translation never blocks the English draft. The English article delivers; the translation is stored with status `needs_review` and its findings, and is not sent to the CMS until fixed or approved. | A missing Latvian version should not cost the English article (Lindevo rule). |
| Model calls | Role **`localize`** (translate; default: the mode's writer) and role **`localize_review`** (native editor; default: the mode's review model). Both can be overridden per site, including subscription models. | Lindevo uses Opus for translating and a cheaper model for review. |
| Translate prompt | Ported from Lindevo's `localize.md`, made site-neutral:<br>- it reads as if written in the target language first;<br>- component tags keep their order and attributes, and only text attributes are translated;<br>- link URLs and citation marks are kept exactly;<br>- the Sources and FAQ headings are localized;<br>- no new or dropped facts;<br>- the glossary wins; the locale's style guide applies;<br>- headings use the locale's convention (for Latvian, infinitive and not imperative), and the slug is ASCII.<br><br>In **revision mode** it fixes exactly the listed problems in the previous attempt and changes nothing else. In **update mode** an existing (possibly hand-edited) translation is the base, and only what changed in the English is updated. | These are Lindevo's lessons: revisions used to retranslate everything, and editor edits were overwritten. |
| Review prompt | Ported from `localize-review.md`. It returns `{fluency 0–10, issues[≤20]{excerpt, field, problem, fix, severity: major\|minor}}`. Each fix is exact replacement wording of about the excerpt's length. **Major issues:** meaning changed, a fact added or dropped, the wrong form of address, missing diacritics, an English word where the glossary has a term, bad grammar, a repeated word form, a heading with the wrong mood. **Minor issues:** unnatural phrasing. | Each fix can be applied in code. |
| Patch before revising | Code applies a reviewer's exact fix when the excerpt occurs **exactly once**, on word boundaries, outside protected spans (code, links, URLs, tags, citation marks), and keeps the same markup characters. Then the text is re-checked. This costs one review call and is not counted as a revision. | It is cheaper and safer than another full translation. |
| Revisions | At most 2 revisions, each editing the failed attempt with the blockers as feedback. **The last passing attempt is kept**: a later failed polish never replaces it. | These are Lindevo's rules. |
| Code checks on the translation | **Parity** with the English: the same components in order (the vendored `lintParity` for the Lindevo profile, and a heading/list/blockquote count for Markdown), the same external citation URLs and numbered marks in order, and one localized Sources list with the same destinations.<br>**Meta:** title and description limits; the slug is ASCII and kebab-case.<br>**FAQ:** a minimum number of questions, each ending in "?", with a minimum answer length.<br>**Formal address:** the locale's forbidden informal forms are blockers (for Latvian: tu/tev/tevi/tevis/tavs…).<br>**Repetition:** adjacent words sharing a stem of 6+ letters are a warning (for Latvian, a leading "jā" is ignored).<br>**Voice:** the site's banned words and phrases. | These are the checks that are objective. |
| Keyword | When DataForSEO is configured, one model call proposes 2–3 target-language keywords ("what people type, not a literal translation"). Code looks up their volume in the locale's market and picks the highest; if all are zero, the model's first choice. The translator then uses it in the title and description and its main words in the slug. If anything fails, the step is skipped. | This is Lindevo's method. |
| Internal links | After translating, `](/blog/<en-slug>)` links (and the site's equivalent path) are rewritten to the linked post's translated URL when BlogFactory has a translation for that post in the locale, using `/<locale>/blog/<slug>`, the Lindevo path. Otherwise the English URL stays, with a warning. | The translator cannot know other posts' translated slugs. |
| Storage | A new table, **`post_translations`**: `id`, `user_id`, `site_id`, `post_id`, `locale`, `title`, `slug`, `description`, `content`, `image_alt`, `keyword`, `status` (`ready`, `needs_review` or `edited`), `findings` (jsonb), `source_revision_id` (the post revision it was made from), `cost_usd`, `created_at` and `updated_at`. Unique on `(post_id, locale)`. Everything is user- and site-scoped. | The translation follows the post's revisions, so it can be marked stale. |
| Staleness | A translation is **stale** when the post's current revision differs from `source_revision_id`. Stale translations are flagged in the UI and not sent to the CMS. "Update translation" re-localizes in update mode. | A stale Latvian version must never ship under a newer English draft (Lindevo rule). |
| Delivery | For the **Lindevo** provider, `push_to_cms_draft` and Send to CMS include `lv: {title, slug, description, content, imageAlt}` on `create_article`/`update_article` when a translation for `lv` is `ready` or `edited` and not stale. A slug conflict retries with `-2`…`-6`. **Other providers:** no translation delivery in v1; the translation stays visible and copyable in BlogFactory. | Lindevo's CMS stores translations on the same article. WordPress and Ghost multilingual setups vary too much for v1. |
| Editing | The post editor gets a language switcher (English, plus each enabled locale). The translated fields can be edited, with optimistic locking (`expectedUpdatedAt`). An edit sets the status to `edited`, and update mode keeps edited wording. | Owner control. Edits are not overwritten. |
| MCP | **No new tool.** `get_post` gains a read-only `translations` summary (locale, status, stale, title, slug). | MCP authority does not grow. |
| Lindevo data | Lindevo's site gets `locales: [lv]` with the 41-term glossary (`lv/glossary.json`), the Latvian style guide (`prompts/partials/latvian-style.md`) and the translating-English-to-Latvian skill (`vendor/translating-english-to-latvian.md`) as its style guide. Formal address forbids tu/tev forms. This is set through the settings API, not code. | It is data, and it stays editable. |

## Out of scope

- Delivering translations for WordPress, Ghost, Wix or Framer.
- Translating images (the cover is shared; only the alt text is translated).
- More than one target locale per run beyond sequential processing.
- Learning from edits (sub-project 6).

## Testing

- **Pure units:** the patch rules, the repeat check, the parity, citation and Sources checks, link rewriting, slug rules, and formal address.
- **The `localize` stage with a fake LLM:** pass, patch-then-pass, revision, the last passing attempt kept, failure leading to `needs_review` while the English still delivers, and update mode keeping edited wording.
- **Routes:** tenant scope, optimistic lock and staleness.
- **Lindevo delivery args:** `lv` is included only when current.
- **Web:** the editor language switcher, and the stale and needs-review states.
- **Real:** one lindevo.com article localized to Latvian on the subscription (Opus to translate, Sonnet to review), read by eye against a published LV post.
